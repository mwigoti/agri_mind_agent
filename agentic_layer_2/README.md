# AgriMind Layer 2

Layer 2 is the agent orchestration and review API. It consumes the custom MCP gateway in `../mcp_server`, and the documented borrowed SQLite MCP server; it does not query platform tables or implement yield prediction.

## Run the local synthetic demonstration

Python 3.11–3.13 is recommended. From the repository root, create a virtual environment, install `agentic_layer_2/requirements.txt`, copy `agentic_layer_2/.env.example` to `.env`, set `API_BEARER_TOKEN` and a reviewer token, then start with:

```bash
python -m agentic_layer_2
```

The default `DEMO_MODE=true` uses only the clearly labelled, hard-coded synthetic fixtures in `synthetic.py`; it does not establish live model, database, satellite, or MCP integration. `GET /health` reports `demo_mode` explicitly. Live mode reports `live` only when `HF_TOKEN` and the required MCP tools are available; otherwise it reports `live_not_ready` and refuses advisory runs. Start an analysis with `POST /api/advisories`, review its pending draft via `GET /api/advisories/{thread_id}`, and decide with the officer token mapped in `REVIEWER_TOKENS` via `POST /api/advisories/{thread_id}/decide`. API calls require `Authorization: Bearer <API_BEARER_TOKEN>`; decisions require an officer-specific bearer token. The outbound payload is simulated and has no real destination.

For local review requests, use JSON such as `{"plot_id":"KE-001"}` and `{"verdict":"APPROVE"}`. The officer identity is derived from the server-side token map and never trusted from request JSON.

## Full MCP and hosted-model integration

Set `DEMO_MODE=false`, configure `HF_TOKEN`, set the model/provider settings, and install the optional upstream dependencies with `pip install -r agentic_layer_2/requirements-integration.txt`. Configure the database variables required by `mcp_server/README.md`. By default the service launches AgriMind through stdio. Set `AGRIMIND_MCP_URL` (and `AGRIMIND_MCP_TOKEN` when the remote server requires it) to use Streamable HTTP instead. Historical SQLite lookup is optional and enabled only with `HISTORICAL_MCP_ENABLED=true`. The agent discovers available tools and validates call arguments against their schemas. The model is hosted by Hugging Face Inference Providers; weights are not downloaded locally. Synthetic task records only should be sent to an external provider.

This environment has not verified remote inference or actual upstream database availability. The live gateway expects numeric field IDs from the shared database; synthetic `KE-*` identifiers belong only to demo fixtures. Historical data is not used as a current observation and remains optional. VRA returns `INSUFFICIENT_EVIDENCE` until zonal measurements and validated rates are available.

## Persistence and safety

LangGraph uses its SQLite checkpointer at `CHECKPOINT_PATH`; audit events append to `AUDIT_PATH`. `POST /api/advisories` returns a thread ID immediately with `RUNNING`; poll `GET /api/advisories/{thread_id}` for the result. `/api/advisories/{thread_id}/decide` requires a reviewer token. No action is accepted unless the checkpoint is paused at `PENDING_APPROVAL`. A decision timestamp is generated by the service. Approval only returns a simulated payload; no SMS or other external action exists. Keep both SQLite files on persistent storage in deployment and protect them as operational records. The Django bridge's default `REVIEWER_TOKEN=dev-reviewer-token` matches the example officer token map; replace both with deployment-specific secrets together.

Through Django, advisory and decision requests require an authenticated field owner or staff user. The decision is recorded in Django, and the generated agronomic narrative remains withheld from the dashboard and report export until an approval newer than that analysis exists. A pending rationale is presented as a draft for the human reviewer; rejection keeps the report withheld.

The local API token and reviewer tokens are demo authentication, not a replacement for platform SSO, role-based authorization, rotation, TLS termination, or an identity provider. Do not expose this demo service publicly.
